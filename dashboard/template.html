Comparaison croisée

Chaque case est un score sur 100 (plus foncé = meilleur), avec la valeur mesurée en dessous. Performance (vitesse, démarrage, mémoire au pic, secondes de CPU, réseau) : score relatif au meilleur navigateur, cible par cible (2× plus lent que le meilleur = 50), puis moyenné sur les cibles. Anti-bot, fidélité et fiabilité : taux absolus. Vitesse, mémoire, CPU, réseau et fidélité ne comptent que les pages de performance et locales : sur une page anti-bot, celui qui passe le challenge charge la vraie page, plus lourde, et serait pénalisé. Survoler une case pour le détail.

Vue d'ensemble

Agrégé sur les cibles sélectionnées ; chargement, RAM, CPU, réseau et fidélité sur les pages de performance et locales seulement. Temps de chargement = moyenne des médianes par cible ; CPU = secondes de processeur consommées par page ; mémoire = , somme sur tout l'arbre de process.

Anti-bot

Chaque case : le verdict de la page (✓ passé, ✕ repéré ou bloqué, ! sans verdict : le script de détection n'a pas tourné dans ce navigateur), puis, sur les pages qui détaillent leurs tests (sannysoft, CreepJS, deviceandbrowserinfo), la barre des contrôles réussis. Un seul contrôle raté suffit pour être repéré : on peut donc réussir 87 % des contrôles et prendre quand même une croix. Browserscan et Cloudflare ne répondent que oui ou non. Survoler une case pour le détail des runs.

Débit en parallèle

Un seul navigateur, N pages qui se partagent une file de chargements (cible : ). Montre combien de pages par minute il tient, et ce que coûte en mémoire chaque page ouverte en plus. Se lance avec npm run throughput.

Pas encore de test de débit dans ces résultats

Le test ouvre plusieurs pages en parallèle dans un même navigateur (1, 2, 4 puis 8) et mesure les pages par minute et la mémoire. Il s'ajoute à la fin d'une campagne complète, ou se lance seul avec npm run throughput, puis npm run dashboard.
